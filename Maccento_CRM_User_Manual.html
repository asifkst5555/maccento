Maccento CRM User Manual

This manual explains how the Maccento website, CRM backend, client portal, AI assistants, sales workflow, invoicing, project tracking, media delivery, and communication tools work together. It is written as a practical operations guide for day-to-day use.

System Type AI-assisted CRM and client portal for real estate media operations.
Primary Users Owner, admin, manager, photographer, editor, client, and agent accounts.
Main Goal Move leads from inquiry to quote, project, invoice, delivery, and client follow-up.

1. System Overview

Maccento CRM is a single operating system for website lead capture, internal sales pipeline management, project tracking, invoice control, media delivery, email communication, and client self-service.

Core Business Purpose

  • Capture new inquiries from the public website.
  • Convert qualified inquiries into quotes and projects.
  • Track operational work from accepted to complete.
  • Control invoice status and project delivery eligibility.
  • Give clients a clean portal for quotes, invoices, requests, and downloads.

Main Product Areas

  • Public website and AI assistant.
  • Lead capture and quote pipeline.
  • Project workspace and media delivery.
  • Email Center and SendGrid-connected communication.
  • Client management and user portal.
Layer What It Does Who Uses It
Website Shows services, package builder, contact form, and public AI assistant. Prospects, clients, agents, marketers.
Admin CRM Manages leads, follow-ups, quotes, invoices, projects, service requests, messages, email, delivery, exports, and settings. Owner, admin, manager, delivery team roles.
Client Portal Lets clients review quotes, invoices, projects, downloads, and service requests. Client, user, and agent roles.

3. Authentication and Roles

3.1 Login and Signup

  • Users access the system through the login page.
  • The signup page can create the first account when no user exists.
  • The first registered account becomes the first admin account.
  • After login, internal roles are routed to the admin dashboard and client-facing roles are routed to the user dashboard.

3.2 Role Model

Role Main Access Scope Typical Use
Owner Full system access, including users and high-level settings. Business control, operations, configuration, approvals.
Admin Full daily CRM operations. Sales, quotes, invoices, projects, email center, delivery.
Manager Broad operations without owner-only user administration. Pipeline supervision, delivery coordination, billing follow-up, and internal team coordination.
Photographer Delivery-focused access. Assigned-project delivery work: upload raw footage (images/videos and raw ZIP), collaborate via project comments, and coordinate with admin/manager.
Editor Delivery-focused access similar to photographer. Assigned-project post-production: upload edited/final media, upload final delivery ZIP, collaborate via project comments, and coordinate with admin/manager.
Client / User / Agent Portal-only access to their own records. Quotes, invoices, media previews/downloads (payment-gated), service requests, project view, project discussion comments, and messages.

4. Admin CRM Modules

4.1 Dashboard

  • High-level operating summary for leads, projects, invoices, client activity, and notifications.
  • Acts as the internal landing page for admins and managers.
  • Supports real-time orientation through the admin assistant and notification center.

4.2 Lead Management

Lead Management is the first operational layer after website capture.

  • All Leads: Complete lead list with filtering and scoring.
  • Leads from AI Assistance: AI-originated inquiry focus.
  • Leads from Packages: Package-builder and pricing-flow leads.
  • Website Submissions: Direct website form submissions.
  • Lead records include status control, notes, follow-ups, outbound email actions, and optional chat export to PDF.

4.3 Quote Pipeline

  • Manual quote creation and review of website/package quote activity.
  • Quote statuses include new, reviewed, contacted, booked, and lost.
  • Custom quotes support line-item adjustment and total recalculation.
  • Preset fixed package quotes are not intended for manual line-item editing.
  • Quote emails can be resent from the admin side.
  • Client portal users can submit revision requests back to the team.

4.4 Invoices

  • Create invoices from client and project contexts.
  • Update invoice status through draft, sent, partial, paid, and overdue.
  • Generate downloadable invoice PDFs for admin and clients.
  • Invoice settings support tax rate configuration and an include-tax-in-PDF toggle.

4.5 Projects

  • Primary operational workspace for active client work.
  • Project statuses include accepted, shooting, editing, and complete.
  • Projects link to clients, invoices, media, and service requests.
  • Assignments support coordinating internal delivery roles (for example, photographer/editor).
  • Assigned Team list is visible inside the client portal project view.
  • Project discussion supports replies, edits, and client-visible collaboration (clients and assigned internal users can participate).
  • Admin users can open client and project contexts directly from project rows.

4.6 Media Delivery

  • Delivery workspace supports Raw Footage and Edited/Final stages for gallery media (images/videos).
  • Raw Footage uploads: gallery files plus optional Raw Footage ZIP (commonly uploaded by the photographer).
  • Edited/Final uploads: gallery files plus Final Delivery ZIP (commonly uploaded by the editor).
  • Uploads are attributed to the uploader (name/role) and stored under project media folders.
  • Assigned photographers/editors can upload and manage media only for projects they are assigned to.
  • Client preview experience: when a project is unpaid, image previews are watermarked; downloads are locked until payment.
  • Final ZIP delivery is available to the client after payment is completed and a final ZIP exists.
  • Watermark settings include logo, position, size, opacity, and rebuild tools where permitted.

4.7 Clients

  • Create and manage client records.
  • Open a full client workspace with projects, invoices, requests, and messages.
  • Switch between all-project view and single-project mode.
  • Use the client page as the central account record for account-level operations.

4.8 Email Center

  • Unified inbox for inbound replies.
  • Sent mailbox with provider event timeline.
  • Draft mailbox with autosave and one-click send.
  • Compose email modal with AI-assisted writing and file attachments.
  • Automation settings and backfill actions for lead follow-up workflow.
  • AI Write generates first-pass draft content from CRM context.

4.9 Users

  • Internal user account management is reserved for high-permission roles.
  • Used to create, review, and remove internal CRM accounts.

4.10 Messages

  • In-app messaging center supports two conversation types: Client Threads and User Direct Messages.
  • Client Threads: Admin/Owner can view and message client threads; messages can optionally be linked to a project.
  • User Direct Messages: Internal users can message admin-team users; Admin/Owner can message any internal user for coordination.
  • Clients can message the admin team from the portal Messages area; replies appear in the same thread for continuity.
  • Messages generate notifications for recipients to reduce missed updates.
  • Works alongside Email Center; use messages for short operational updates and email for formal threads.

4.11 Form Submissions

  • Lists website contact-form submissions for review and follow-up.
  • Supports opening submission detail, updating status, and deleting spam submissions.

4.12 Exports (CSV)

  • Export leads, quotes, and follow-ups to CSV for reporting and offline review.
  • Use exports for periodic performance snapshots and pipeline tracking.

4.13 Follow-Ups

  • Leads can have follow-ups scheduled with due dates and notes.
  • Follow-up status can be updated as work is completed.

4.14 Service Requests (Admin Handling)

  • Service requests are submitted from the client portal and attached to a client and optionally a project.
  • Admins can update service request status through new, accepted, in_progress, completed, and closed.
  • Use service requests to track add-ons, revisions, and post-delivery work.

4.15 Notifications

  • Top-bar notification bell shows an unread counter and a quick feed (latest items).
  • Notifications can be filtered by category: All, Quotes, Invoices, and Messages.
  • Each notification may include an action link (Open) to jump to the relevant screen.
  • Supports marking individual notifications as read and using Mark all read to clear the badge.
  • Common quote notifications: new quote submission, quote status updated, quote revision requested.
  • Common invoice notifications: invoice created, invoice status updated.
  • Common message notifications: new admin message, direct message received, new service request, service request status updated, project assigned, project status updated, project comment added, admin email sent, client email reply received.

5. Client Workspace and Portal

5.1 Client Dashboard

The client dashboard is the customer-facing workspace after login.

  • Lead visibility for client-owned inquiries.
  • Quote listing with direct open action.
  • Request New Service form.
  • Project list with detailed popup view.
  • Invoice downloads and project-linked invoice visibility.
  • Media preview, media download, and final ZIP download when eligible.
  • Account page for contact details and profile context.
  • Messages center for client-to-admin communication.

5.2 Client Project Experience

  • Each project can show status, schedule, invoices, and related service requests.
  • Assigned Team shows which internal users are attached to the project.
  • Project Discussion enables threaded comments (reply, edit, delete your own comments).
  • Clients can submit additional service requests linked to a project.
  • Project downloads are controlled by payment state (downloads unlock after invoice/project is marked paid).
  • Image previews are watermarked until the project is paid; downloads are locked until payment.

5.3 Client Service Requests

Service requests are the client-side request-and-follow-up mechanism.

  • Clients can request new work from their dashboard or from a project context.
  • Service request statuses include new, accepted, in_progress, completed, and closed.
  • Admins can review and update these requests from the CRM.

6. AI Assistants

Public AI Assistant

  • Answers service, package, booking, and recommendation questions.
  • Uses company service knowledge, package guidance, and delivery expectations.
  • Should not invent custom pricing or unsupported policies.
  • For policy questions outside configured rules, it directs visitors to email or call the team.

Admin Assistant

  • Available across the admin panel as an internal operations helper.
  • Answers practical CRM workflow and navigation questions.
  • Uses role-aware and module-aware CRM knowledge.
  • Does not claim to have changed records or completed actions.
Assistant Audience Primary Topics

Admin Assistant Internal staff CRM workflows, invoices, projects, clients, media delivery, lead operations, email center.

7. Email Center and Communication Workflow

7.1 Email Center Functions

  • Inbox stores inbound replies parsed into the CRM.
  • Sent view shows outbound emails and provider event tracking.
  • Drafts support autosave, edit, manual save, send, and delete.
  • AI draft writing helps generate first-pass outbound emails.
  • Compose email supports direct recipient routing, reply-to, CC, BCC, project tagging, and attachments.

7.2 SendGrid Integration

  • Outbound messages create email logs for CRM tracking.
  • SendGrid webhook events can update delivery/provider timeline visibility.
  • Inbound replies can be parsed into inbox records and linked to client/project context.
  • Project thread tags support more reliable email-thread mapping.

7.3 Compose Attachments

  • Admins can attach up to 5 files in compose.
  • Each attachment supports up to 10 MB.
  • Attachments are sent with the outbound email but are not stored in drafts.

8. Media Delivery and Payment Rules

8.1 Delivery Workspace

  • Gallery upload area for images and videos.
  • Final ZIP upload area for client-ready delivery package.
  • Media preview actions for internal users.
  • Delivery state visibility from client and project views.

8.2 Watermark Logic

  • Watermark settings exist for authorized roles only.
  • Rebuild actions apply to preview/media workflow where configured.
  • When unpaid, clients can still preview media, but images are watermarked to protect delivery.
  • Watermark controls are not intended as a replacement for final paid delivery packaging.

8.3 Payment Gate

Client downloads are locked until the related project is paid. Image previews remain available with watermarking when unpaid, and final ZIP downloads unlock only after payment is complete. This rule protects final delivery access and is one of the most important operational controls in the CRM.

10. Typical Operational Flow

  1. A visitor uses the AI assistant, package builder, or contact form.
  2. The system captures the inquiry into the CRM as a lead or submission source.
  3. Admin reviews the lead, updates status, follows up, and may create a quote.
  4. Once accepted, work progresses into a client and project context.
  5. Invoices are created and tracked.
  6. Media is uploaded and final delivery is prepared.
  7. Once payment is complete, the client can access final media and ZIP downloads.

11. Operational Notes and Known Business Rules

  • Primary on-site service area is Greater Montreal.
  • Special locations can be discussed case by case.
  • Typical turnaround: photos in 24-48 hours, video around 72 hours.
  • Drone work depends on weather and safe flight conditions.
  • The current CRM knowledge base does not define automatic late fees, cancellation policy, or refund policy.
  • When those policy questions arise, staff should direct the client to the business team by phone or email for confirmation.

12. Troubleshooting Guide

Issue Likely Cause Recommended Check
Cannot log in Empty user table, wrong active database, invalid credentials, or stale browser cookies. Check user count, active DB connection, and clear browser cookies/session.
Client cannot download media Invoice/project is not marked paid, or final delivery is not uploaded. Review invoice status and project delivery files.
Inbound email not visible SendGrid webhook/config issue, unmatched inbound parse, or message-body problem. Check Email Center inbox, webhook route activity, and recent logs.
Attachment missing from sent email Attachment not selected, validation size exceeded, or send failed before dispatch. Review compose form selection, validation, and sent mailbox record.
Admin sees blocked action in UI Role mismatch or outdated page state. Confirm the user role and refresh the page after permission changes.

13. Feature Summary

Maccento CRM is not just a back-office admin panel. It is a full lead-to-delivery operating system with a public marketing front end, dual AI assistants, a quote and invoice pipeline, client portal functions, media delivery controls, and integrated email communication.

In day-to-day use, the system should be understood as a connected workflow: website inquiry -> CRM review -> quote -> project -> invoice -> delivery -> client access.
